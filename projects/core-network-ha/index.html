企業核心網路高可用性建置

從既有單點架構出發，規劃雙 FortiGate 91G Active-Passive HA、雙 FortiSwitch FS-424E MCLAG 與 10G FortiLink 交叉備援；並在現場面對 HA 同步異常及非授權 DHCP 干擾時，以營運優先原則完成服務復原與根因定位。

專案類型核心網路備援
主要設備FortiGate / FortiSwitch
核心技術HA / MCLAG / FortiLink
我的角色規劃、建置、排錯、文件
01

BACKGROUND

專案前因

原始環境

客戶的核心網路承載辦公區、各樓層接取交換器、Server Farm、虛擬機、儲存設備與對外網路。既有架構中，防火牆與核心交換層缺乏完整的設備及路徑備援，任一核心設備或上行鏈路故障，都可能擴大成全場斷線。

建置目標

在不影響既有營運的前提下，新增備援防火牆與第二台核心交換器，消除單點故障；同時建立可驗證、可回復的施工程序，讓故障切換不只存在於架構圖，而能經過實際測試。

單點風險 01防火牆故障將中斷閘道服務
單點風險 02核心交換器故障影響全場網路
單點風險 03上行路徑缺少交叉備援

03

PLANNING

施工規劃與風險控制

PHASE 01

建立防火牆 HA

完成授權與韌體版本對齊、備份主機設定，離線確認 HA 模式、群組與優先權，再接上 Heartbeat，避免空白備機反向覆蓋營運中主機。

PHASE 02

核心交換器納管

採單機漸進式接入，先完成 FortiLink 授權與基本拓樸確認，再加入第二台設備，降低未授權設備或 STP 尚未收斂造成廣播風暴的風險。

PHASE 03

建立 MCLAG 骨幹

使用指定光纖埠建立 ICL Peer Link，確認雙向認證、Keepalive 與 MCLAG 狀態，再補上交叉上行鏈路。

PHASE 04

驗證與故障切換

比對 HA Checksum、檢查 ICL 成員埠、執行雙向流量測試，並模擬單一設備或鏈路中斷，驗證服務連續性。

風險可能影響預防與復原方式
HA 同步方向錯誤

備機空白組態覆蓋主機，造成全網中斷。

離線雙重確認 Priority 與同步方向，施工前保留完整設定備份。

Heartbeat 中斷

可能形成 Split-Brain，引發 MAC Flapping。

預先規劃實體隔離、Console 登入、線路修復及重新同步程序。

MCLAG／STP 未收斂

可能引發廣播風暴或特定 VLAN 中斷。

採逐步上線，不一次插滿所有線路；先授權、驗證，再加入備援路徑。

04

ON-SITE EXECUTION

施工當天發生了什麼

10:00

工程團隊進場

啟動核心網路升級，依計畫先處理防火牆 HA，再進行核心交換器備援。

10:10–13:00

HA 叢集成形，但顯示未完全同步

兩台防火牆已完成 Active-Passive 選舉，Heartbeat 通訊正常，Primary／Secondary 角色也已建立；但系統仍顯示同步異常，Checksum 比對發現 Global 與 All 區域不一致。

同時進行

CoreSW 納管與 MCLAG 建立

第二台核心交換器完成授權，兩台 FS-424E 透過 ICL 成員埠形成 MCLAG，Keepalive 封包雙向收發，叢集骨幹成功建立。

13:20–16:00

整線、標籤與 HA 深入除錯

完成機櫃線路整理與標籤化，同時比對主備設定校驗碼、HA 狀態與同步差異，避免在狀態未明時直接進行切換。

16:30

啟動服務復原機制

考量廠區營運優先，先保留 HA 異常現場，將網路復原至可穩定提供服務的架構，而不是為了完成施工而持續擴大中斷時間。

17:20–18:30

有線恢復，但無線網路仍異常

有線端點測試正常；無線端點取得的 IP 網段卻不屬於核心防火牆所派發的 VLAN。透過封包與 DHCP 行為判斷，現場存在非授權 DHCP Server。

18:30–19:30

定位非授權 DHCP 來源

逐層進行實體環境排查，找到接入企業網路的家用 Wi-Fi 分享器並隔離，終止錯誤 DHCP Offer 與 IP 派發衝突。

19:30–20:00

服務恢復與驗收

廠區網際網路與內網恢復穩定，逐一完成核心、樓層接取及終端連線驗證。

05

TROUBLESHOOTING

兩個問題，兩條判斷路徑

ISSUE 01

HA 為什麼「有成形」卻「未同步」？

  • 角色選舉成功，不等於所有組態已同步。
  • Heartbeat 正常，只能證明節點間通訊存在。
  • 必須再比對 Cluster Checksum；本案 Root 區域相同，但 Global 與 All 不一致。
  • 因此保留現場狀態並繼續除錯，而不是直接宣告 HA 完成。
ISSUE 02

為什麼有線正常、Wi-Fi 卻拿到錯誤 IP？

  • 先區分實體連線、VLAN 與 DHCP 三個層次。
  • 終端取得的網段不屬於核心防火牆，排除單純 AP 訊號問題。
  • 封包行為指向同一廣播域內存在第二個 DHCP Server。
  • 透過逐區隔離與實體排查，定位家用分享器並移除。
